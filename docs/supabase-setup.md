# Настройка Supabase для Lounge OS

## 1. Создание проекта

Создайте проект Supabase в ближайшем к пользователям регионе. В настройках Auth
добавьте URL опубликованного приложения в список разрешённых redirect URL:

```text
https://kenigsfels.github.io/lounge-os-app/
```

Для локальной разработки также добавьте:

```text
http://127.0.0.1:8765/
```

## 2. Схема и безопасность

Примените SQL-файл `supabase/migrations/202608100001_initial_schema.sql` через
SQL Editor или Supabase CLI. Миграция создаёт:

- профили пользователей;
- заведения и участников с ролями `owner`, `admin`, `employee`;
- сотрудников;
- автоматическое первое заведение для нового пользователя;
- RLS-политики и Realtime для сотрудников.

Не отключайте RLS и не добавляйте публичные политики для `anon`.

## 3. Переменные приложения

Используйте только Project URL и publishable/anon key:

```text
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
```

`service_role` key имеет административные права и запрещён в браузере.

## 4. GitHub Pages

Добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в
`Settings → Secrets and variables → Actions`. Workflow соберёт приложение с
этими параметрами и опубликует каталог `dist`.

## 5. Проверка

1. Откройте опубликованное приложение.
2. Перейдите в «Настройки».
3. Запросите magic link для email владельца.
4. После входа создайте сотрудника.
5. Откройте приложение в другом браузере и войдите тем же email.
6. Убедитесь, что сотрудник появился после синхронизации.
