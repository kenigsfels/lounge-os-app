# Модель данных сотрудников

Данные сотрудников хранятся в LocalStorage под ключом `sylon_employees`. Префикс `sylon_` добавляется универсальным слоем `core/storage.js` и позволяет очищать данные SYLON, не затрагивая данные других приложений.

## Структура сотрудника

```js
{
  id: string,
  name: string,
  position: string,
  phone: string,
  status: "active" | "inactive",
  rate: number,
  startDate: string,
  notes: string,
  createdAt: string,
  updatedAt: string
}
```

`createdAt` и `updatedAt` содержат ISO-строки. Новому сотруднику по умолчанию назначаются статус `active` и ставка `0`.

## Доступные функции

- `getEmployees()` — возвращает копию массива сотрудников.
- `getEmployeeById(id)` — возвращает копию сотрудника или `null`.
- `createEmployee(data)` — валидирует и создаёт сотрудника.
- `updateEmployee(id, changes)` — валидирует и сохраняет изменения.
- `deleteEmployee(id)` — удаляет сотрудника и возвращает `boolean`.
- `seedEmployees()` — создаёт три тестовые записи, только если база пуста.
- `clearEmployees()` — удаляет только данные сотрудников.

Универсальные операции `readStorage`, `writeStorage`, `removeStorage` и `clearAppStorage` находятся в `core/storage.js`.

## Валидация

Имя и должность обязательны. Телефон и статус необязательны; статус может быть только `active` или `inactive`. Ставка необязательна, но при наличии должна быть конечным числом не меньше нуля. Все текстовые поля очищаются от пробелов по краям, а повторяющиеся пробелы нормализуются.

## Переход на серверную базу

UI и бизнес-логика должны обращаться только к функциям `core/employees.js`. Для перехода на сервер нужно заменить внутренние вызовы слоя хранения на запросы к API и сделать операции асинхронными, сохранив публичные форматы результатов `{ success, employee }` и `{ success, errors }`. Компонентам интерфейса тогда потребуется только ожидать Promise, без знания структуры базы данных.
